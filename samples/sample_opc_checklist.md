## 一、下单前需求问卷（节选）

> 用法：客户来问价时，先把这份问卷发过去。填不完整的，先不报价。

### A. 基本信息

1. 项目名称或仓库地址：
2. 项目来源（自己写的 / 开源的 / 公司内部）：
3. 使用场景一句话：
4. 期望完成时间：

### B. 环境信息

5. 操作系统与版本（Windows 10/11、macOS 版本、Linux 发行版）：
6. 是否有管理员权限：
7. 是否能接受远程协助（向日葵 / ToDesk / 系统自带）：
8. 是否使用 GPU；如有，型号与驱动版本：

### C. 卡点信息

9. 现在能进行到哪一步（未开始 / 已安装 / 能启动 / 能访问 / 能跑通功能）：
10. 报错原文或截图（不要只写“报错了”）：
11. 已经试过哪些方法，结果如何：
12. 是否有必须保留的数据或配置：

### D. 边界确认

13. 项目是否可合法使用，是否涉及破解、去授权、绕过风控：
14. 是否需要代管账号密码或涉及支付、实名：
15. 服务器、域名、API 额度等第三方费用由谁承担：

### 分流规则（内部用）

| 情况 | 处理 |
| --- | --- |
| 信息不全 | 先让客户补齐第 9–11 项，再报价 |
| 涉及破解 / 去授权 / 隐私数据 | 直接拒绝，不报价 |
| 预算明显低于基础档 | 推荐更小的范围，或直接说明做不了 |
| 多服务 / GPU / 内网 | 按复杂档评估，先说明可能超时 |

## 二、部署验收单（节选）

> 用法：交付时和客户逐项确认，截图或录屏留档；未通过的项目写清原因和下一步。

| 序号 | 验收项 | 通过标准 | 结果 | 备注 |
| :---: | --- | --- | :---: | --- |
| 1 | 环境依赖 | 依赖安装完成，版本与项目要求一致 | □ 通过 □ 未通过 | |
| 2 | 启动命令 | 按文档命令能启动，无报错 | □ 通过 □ 未通过 | |
| 3 | 访问入口 | 本地或约定地址能打开 | □ 通过 □ 未通过 | |
| 4 | 核心功能 | 约定的 1–2 个功能可实际操作 | □ 通过 □ 未通过 | |
| 5 | 配置说明 | 模型 / API / 端口等配置已写清 | □ 通过 □ 未通过 | |
| 6 | 启停与重启 | 客户能按说明自行启动、停止、重启 | □ 通过 □ 未通过 | |
| 7 | 遗留问题 | 未完成项、原因、下一步已写明 | □ 已写 □ 无 | |

- 客户确认（文字或邮件回复即可）：____________________

### 验收边界

- 验收只覆盖本单约定的项目与功能，不含新增需求。
- 第三方服务（模型 API、域名、服务器）故障不计入交付问题，但会协助定位。
- 客户环境变更、权限收回或自行修改配置导致的故障，重新排查按新单计价。

## 三、这套模板怎么改成自己的

1. 把三档价格和范围换成你的真实报价。
2. 把“不接什么”换成你的真实边界，不要保留做不到的承诺。
3. 把验收项改成你能当场演示的项目。
4. 每接 5 单，把新问题补进问卷和 FAQ。
